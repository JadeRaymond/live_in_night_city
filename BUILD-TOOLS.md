# Reelkeep 1.23 — инструменты для внешней сборки

Этот комплект дополняет первоначальный архив исходников. Он создаёт нужную
папку `tools/`, проверяет Java и позволяет собрать полный неподписанный ARM64 APK.
Внутри комплекта только текст: скрипты, список зависимостей и инструкция.
Ключ релизной подписи, пароли, cookies и сессии не передаются.

## Требования

Linux x86_64, Bash, Python 3.9+, JDK 17+ (проверено на JDK 21), `zip` и доступ
к интернету. Это инструменты для Linux-среды Claude/компьютера, а не приложение
для установки в Android. Если у Claude нет выполнения команд, эти файлы сами
по себе не создадут терминал.

## 1. Распаковка

Распакуйте оба ZIP в один каталог. У обоих архивов общий верхний каталог
`Reelkeep-source-review-1.23/`, поэтому их содержимое объединится.
В корне рядом должны находиться `app/`, исходный `build.sh`, новый
`setup-tools.py`, `check-java.sh`, `restore-runtime.py`, `build-unsigned.sh`
и `tools/dependency-lock.json`.

Исходники:
https://raw.githubusercontent.com/JadeRaymond/live_in_night_city/reelkeep-source-review-1.23/Reelkeep-1.23-source-review.zip

## 2. Восстановление tools

```sh
cd /path/to/Reelkeep-source-review-1.23
python3 setup-tools.py
```

Скрипт загрузит около 170 МБ зависимостей и извлечёт только нужные файлы:

- Android SDK API 35 (`tools/android-35/android.jar`).
- Android build-tools 35.0.0: aapt2, D8, zipalign, apksigner и зависимости.
- Eclipse ECJ 3.38.0.
- Java API ONNX Runtime Android 1.23.2.
- Java API Tesseract4Android 4.9.0.

В исходном проекте папка build-tools исторически названа `android-15`.
Это не номер версии: внутри используется build-tools 35.0.0.
Все адреса и SHA-256 зафиксированы в `tools/dependency-lock.json`.
После скачивания хеши проверяются до использования; повреждённый файл
не устанавливается. Поддерживается `--cache /path/to/cache` для готовых загрузок.

## 3. Проверка Java без моделей и runtime

```sh
bash check-java.sh
```

Команда генерирует R.java из оригинальных ресурсов, компилирует ВСЕ Java-файлы
через ECJ и выполняет D8 с зависимостями. Результат — скомпилированные классы
и DEX в `build/`. Проверка не требует app/assets/, нативных библиотек или ключа.
Она предназначена для проверки правок Java и не выдаёт неполный APK за
готовое работающее приложение.

## 4. Восстановление отсутствующих ресурсов для полной сборки

Исходный обзорный архив намеренно не содержал app/assets/ и native runtime.
Одних tools недостаточно для полнофункционального APK. Передайте Claude
также исходный APK Reelkeep 1.23 как локальный файл. При необходимости APK
можно передать как ZIP: APK уже имеет формат ZIP, распаковывать его заранее
не надо. Расширение файла не важно для следующего скрипта.

```sh
python3 restore-runtime.py /path/to/Reelkeep-1.23.apk
```

Скрипт принимает только известный исходный APK с SHA-256:
`f6846c6c99471397cc1c17c4d7ca6b34a6432ce110d47cee6b49080a8187fd13`.

Из него извлекаются:

- app/assets/: реальный WebView UI, модели, OCR-данные, шрифты, runtime и notices;
- build/native/lib/arm64-v8a/: нативные библиотеки.

Java, AndroidManifest.xml и res/ из APK НЕ восстанавливаются и НЕ подменяют
редактируемые исходники. При конфликте с уже изменённым файлом assets скрипт
останавливается; выполняйте восстановление в чистом экспорте до правок assets.
Модель не обучается и ресурсы не скачиваются по незакреплённым версиям.
Ключ подписи из APK получить нельзя, и этот комплект его не содержит.
Пользовательские данные/сессии в APK отсутствуют.

## 5. Полная сборка без подписи

```sh
bash build-unsigned.sh
```

Выход: `build/reelkeep-unsigned.apk`.
Полная цепочка: aapt2 → ECJ → D8 → упаковка assets и native → zipalign.
Восстановленные assets и runtime — исходной версии 1.23; Java берётся из
ваших текущих редактируемых файлов. Предыдущие исходники Java остаются
нетронутыми, кроме ваших правок.

Если Claude меняет только Java, достаточно после восстановления ресурсов
повторно запускать `bash build-unsigned.sh`. Подпись для компиляции не нужна.

## 6. Подпись только собственным ключом проверяющего

Неподписанный APK нельзя установить как обычный подписанный релиз.
Проверяющий при необходимости создаёт СОБСТВЕННЫЙ локальный ключ:

```sh
keytool -genkeypair -keystore /outside/project/review.jks -alias review -keyalg RSA -keysize 2048 -validity 3650
./tools/android-15/apksigner sign --ks /outside/project/review.jks --out build/reelkeep-review.apk build/reelkeep-unsigned.apk
./tools/android-15/apksigner verify build/reelkeep-review.apk
```

Пароль вводится локально интерактивно, в комплекте нет значения пароля.
Такая подпись отличается от подписи установленного Reelkeep: это НЕ обновление
для установки поверх основного релиза. Для итогового обновления Java-правки
нужно вернуть владельцу проекта для сборки с прежним ключом.

## Проверено

- Источники загрузок доступны; архивы сверены с зафиксированными SHA-256.
- В отдельном чистом каталоге инструменты установлены из проверенного кэша
  тех же архивов (повторная полная сетевая загрузка не выполнялась).
- Компиляция ресурсов, всех Java и D8 и полный неподписанный APK проверены.
- Установка этого неподписанного APK на телефон не выполнялась.
